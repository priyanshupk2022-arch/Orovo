## 2025-02-27 - FastAPI Async Routing Anti-Pattern with Synchronous Clients
**Learning:** Using synchronous network clients (like `stripe.checkout.Session.create` or `Groq()`) inside `async def` FastAPI routes forces the network I/O to execute on the main event loop thread. Since FastAPI relies on a single event loop to handle concurrent async requests, this blocks the entire application from serving other requests until the synchronous network call completes. Even if a library doesn't inherently look "blocking" in code, any network I/O must be natively async in `async def` endpoints, or the route must be downgraded to a standard `def` (which FastAPI runs in a separate thread pool).
**Action:** When inspecting FastAPI applications, prioritize reviewing `async def` endpoints that make external API calls. Ensure that the associated SDK provides asynchronous equivalents (like `stripe.checkout.Session.create_async` or `AsyncGroq()`) and that the underlying HTTP transport (e.g. `httpx`) is installed and configured to support it. If no async equivalent exists, downgrade the route to `def` to avoid event loop blocking.
